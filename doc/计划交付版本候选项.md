# 迭代需求的计划交付版本

计划交付版本使用版本管理中的「迭代版本（B 构建）」。产品需求和领域需求共用同一份候选目录，新增、行内编辑和批量修改的选项一致。

## 发布状态与候选项

- B 构建是否已发布，只根据该构建自身的实际发布日期判断；日期已到（含当天）才算已发布。
- 父版本的实际发布日期不会替其下全部 B 构建判定状态。父版本发布后，新建或计划在未来发布的构建仍可选择。
- 默认隐藏已发布构建，并显示隐藏数量；勾选「显示已发布版本」后，可以直接选择历史构建补录需求，选项中会标注「已发布」。
- 开关在产品/领域标签间共享。已有需求中的历史版本保持显示，候选项隐藏不会清空已保存的版本。
- 批量修改中尚未提交的选择若被开关隐藏，会清空临时选择，避免在候选项变化后误提交。

## 刷新与数据来源

「刷新版本」重新读取 `GET /api/iteration-versions/all`，可在新增构建后直接更新候选项。加载失败会显示错误及 HTTP 状态；已有成功加载的目录保留，支持再次刷新。

接口返回完整 B 构建目录和各自的 `released` 标记，由迭代详情决定是否展示已发布项。问题单的实际合入构建仍使用完整目录。客户定制化需求所用的普通版本发布状态按普通版本自身日期判断。

顶部「按计划交付版本筛选」用于筛需求，只列当前需求数据中已使用的版本及数量，与编辑时可选的完整候选目录用途不同。

此修复不修改历史需求或版本日期，不涉及数据库迁移。
