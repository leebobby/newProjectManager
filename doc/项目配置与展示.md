# 项目配置与页面展示

修改部署实例的 `backend/config.json`。只有该文件不存在时，后端才使用 `backend/config.example.json`；模板中的修改不会覆盖已有实例配置。

可以在现有 JSON 对象中添加或更新下面这些字段，保留其余采集路径、词表等配置：

```json
{
  "project_name": "新项目管理系统",
  "project_description": "本项目的目标与简介",
  "about_content": "新项目管理系统\n\n项目介绍\n\n维护团队",
  "hero_badges": ["研发", "验证", "交付"]
}
```

系统名称优先取非空 `project_name`；未设置或为空时取 `about_content` 首行，最后回落到“项目管理系统”。简介优先取 `project_description`，为空时取关于内容中标题后的第一段。关于内容作为独立正文保留，不会因单独修改名称而自动改写。

页面内保存配置后，名称和简介立即同步。直接编辑配置文件后刷新页面即可生效，无需重启后端或重新构建前端；切换路由、重新聚焦窗口也会重新读取名称配置。读取暂时失败时保留上次成功读取的名称。

## 展示位置排查

| 配置 / 展示位置 | 排查结果与处理 |
| --- | --- |
| 登录标题、左上角名称、折叠简称 | 共用 `store/projectConfig.js`；修复侧栏固定名称与“岳”字简称 |
| 浏览器标签页、项目简介页标题和标识 | 统一读取系统名称，去掉固定“岳麓山”文案 |
| 首页简介、关于内容 | 改为共享配置；页面保存后同步更新 |
| `hero_badges` | 保留配置中的顺序，空列表不显示标签；修复清空后又显示技术栈默认标签的问题 |
| `issue_api_projects` | 问题单项目 Tab 按配置名称与顺序显示；修复空列表仍显示 YLS3000/5000/8000 的问题 |
| `current_stages` | 客户面状态页通过配置接口加载阶段下拉；修改文件后刷新页面重新读取 |
| `product_features` | 产品需求页通过配置接口加载特性选项；保存后更新当前页面选项 |
| 硬件清零来源、选项、颜色、自定义列 | 硬件清零页通过配置接口加载；页面保存后重新读取配置 |
| 问题单路径、采集项目、统计部门、小组、采集时间 | 问题单配置页按键加载和保存；后端按请求读取运行时配置，定时采集设置保存后更新调度 |
| 业务记录与导出 | 项目、版本、专项、WBS 等名称来自对应数据库记录；修改系统名称不会重命名这些业务记录。未发现导出代码中固定使用“岳麓山”作为系统名称 |

配置接口禁用 HTTP 缓存，每次读取加载当前文件。GET/PUT 响应同时更新共享展示状态，旧的读取响应不会覆盖刚保存的配置。

验证包含：直接编辑文件后再次读取、部分保存保留其他配置、登录至首页的名称一致性、页面保存立即更新、折叠简称、空标签与空采集项目、重新聚焦读取及配置读取失败时保留名称。
